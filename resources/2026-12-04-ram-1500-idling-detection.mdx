To detect idling on a Ram 1500, query the DIMO Telemetry API for segments with the idling detection mechanism. DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals. Idling detection requires a DIMO device, and on a Ram 1500 both the DIMO LTE R1 and AutoPi support idling and report engine RPM.

## Steps

1. Create a Developer License in the Developer Console and generate an API key. You need your `Client ID`, `Redirect URI` and `API Key`.
2. Get the Ram 1500 shared with your app. Vehicle owners consent to and control sharing, so builders get data with clear provenance. Sharing is done through DIMO Connect.
3. Get a Developer JWT, then exchange it for a Vehicle JWT through the Token Exchange API. Request the "All-time, non-location data" permission (privilege 1). The start and end locations in each segment are location data, so request the location permission you need as well (for example "All-time location", privilege 4).
4. Call the `segments` query on the Telemetry API with your Vehicle JWT in the `Authorization` header. Set `mechanism` to `idling`. The date range can be at most 31 days.
5. Tune detection with `config`. `maxIdleRpm` sets the upper bound for idle RPM (default 1000, min 300, max 3000). `minSegmentDurationSeconds` filters out very short segments (default 240). `signalCountThreshold` controls sensitivity (default 10).
6. Read `start`, `end`, `duration` and `isOngoing` from each returned segment. If `isOngoing` is true, the segment extends beyond your query range and `end` is not included.
7. Optionally request extra aggregates per segment through `signalRequests`, such as the maximum of `powertrainCombustionEngineSpeed` to confirm the engine stayed in the idle range.

The DIMO LTE R1 on a Ram 1500 (2013 and newer) and AutoPi (2012 and newer) both report `powertrainCombustionEngineSpeed`. The DIMO LTE R1 also reports `isIgnitionOn`. You can use that signal to cross-check whether the ignition was on during a segment. The AutoPi listing for this truck does not include it.

DIMO adds vehicle-state depth on top of GPS tracking; it doesn't replace it.

For the full list of signals on this truck, see the vehicle page at [/vehicles/ram/1500](/vehicles/ram/1500).

## Code

```graphql
query GetIdlingSegments {
  segments(
    tokenId: 117315
    from: "2025-11-01T09:21:19Z"
    to: "2025-11-07T09:21:19Z"
    mechanism: idling
    config: {
      maxIdleRpm: 1000
      minSegmentDurationSeconds: 240
    }
    signalRequests: [
      { name: "powertrainCombustionEngineSpeed", agg: MAX }
    ]
    limit: 50
  ) {
    start {
      timestamp
      value { latitude longitude }
    }
    end {
      timestamp
      value { latitude longitude }
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

Send this query to https://telemetry-api.dimo.zone with the header `{ "Authorization": "<yourVehicleJwt>" }`. Replace the example `tokenId` and the date range with your own values.

## FAQ

### Which Ram 1500 hardware supports idling detection?
The DIMO LTE R1 (2013 and newer) and AutoPi (2012 and newer) both list idling for the Ram 1500. The documentation states that idling detection requires a DIMO device.

### How does DIMO decide a period is idling?
Idling segments are contiguous periods where engine RPM stays in the idle range. You set the upper bound with `maxIdleRpm`, which defaults to 1000.

### How do I ignore short stops?
Raise `minSegmentDurationSeconds`, which defaults to 240 seconds (4 minutes) and accepts values from 60 to 3600. Segments shorter than this are left out of the results.

### How far back can I query?
The maximum date range for a `segments` query is 31 days. For longer periods, run several queries and page through results with `limit` and `after`.
