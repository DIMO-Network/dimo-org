To verify an odometer reading on a Tesla Model X, read the odometer signal with the DIMO Telemetry API and request an odometer statement attestation for the vehicle with the Attestation API. On a Tesla Model X (2016 and newer), the Tesla connection (OEM cloud, no hardware) reports the odometer in kilometers as `powertrainTransmissionTravelledDistance`.

DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals. Vehicle owners consent to and control sharing, so builders get data with clear provenance.

See the full signal list on the [Tesla Model X vehicle page](/vehicles/tesla/model-x). A version of this guide for any connected vehicle is at [How to Verify Mileage at Rental Return with DIMO](/resources/verify-mileage-at-rental-return).

## Steps

1. Create a Developer License in the [Developer Console](https://console.dimo.org/sign-in) and generate an API Key. You need your Client ID, Redirect URI and API Key.
2. Get a vehicle shared with your app. The owner shares the Model X through DIMO Connect, and you need the vehicle's token ID.
3. Get a Developer JWT, then exchange it for a Vehicle JWT through the Token Exchange API. Request the permission for all-time, non-location data (privilege 1), which is the permission the odometer signal falls under.
4. Read the current odometer with the Telemetry API `signalsLatest` query and the `powertrainTransmissionTravelledDistance` signal. On the Model X this signal is reported in km by the Tesla connection.
5. Request an odometer statement attestation with the Attestation API (`POST /v2/attestation/odometer-statement/:tokenId`), sending the Vehicle JWT. The `timestamp` parameter is optional.
6. Handle the response as a confirmation only. It is a message that the credential was generated for retrieval through the Telemetry API, and it carries no odometer value. Keep the km reading from step 4 to show alongside the signed statement.

## Code

This example requests an odometer statement attestation for a vehicle. It assumes you already have a Vehicle JWT. Replace `12345` with the vehicle's token ID.

```typescript
const odometerVc = await dimo.attestation.createOdometerStatementVC({
  vehicleJwt: "eyJhbGc...ILlujqw",
  tokenId: 12345
})
```

To read the latest odometer value for the same vehicle, send this query to the Telemetry API with the Vehicle JWT in the `Authorization` header, in the form `Bearer <Vehicle JWT>`:

```graphql
query GetLatestOdometer {
  signalsLatest(tokenId: 12345) {
    powertrainTransmissionTravelledDistance {
      value
      timestamp
    }
  }
}
```

Want to run it on a real Model X? Start with a Developer License from the [Developer Console](https://console.dimo.org/sign-in), then go through the [authentication guide](/docs/getting-started/authentication).

## FAQ

### Which signal gives the Model X odometer?
The Tesla connection reports `powertrainTransmissionTravelledDistance`, labeled Odometer, in km.

### Do I need the owner's permission?
Yes. A vehicle must be shared with you before you can fetch a Vehicle JWT, and the owner controls what is shared.

### Is the timestamp parameter required for the odometer statement?
No. `timestamp` is optional for the odometer statement request.

### Can I read historical odometer values?
The Telemetry API `signals` query retrieves signal data for a given time period, using `from`, `to` and `interval` arguments.
