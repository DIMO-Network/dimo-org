To detect idling on a Toyota Corolla, query idle segments from the DIMO Telemetry API using a vehicle that has a DIMO device. Both the DIMO LTE R1 and the AutoPi report idling for the Corolla, and both report engine RPM, which is what idle detection is based on. DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals.

Vehicle owners consent to and control sharing, so builders get data with clear provenance. See the [Toyota Corolla vehicle page](/vehicles/toyota/corolla) for the full list of supported signals.

## Steps

1. Create a Developer License in the Developer Console and note your Client ID, Redirect URI and API Key.
2. Get a Corolla shared with your app. The owner grants access through DIMO Connect, and you need a vehicle shared with you before you can fetch a Vehicle JWT.
3. Get a Developer JWT, either the system-generated one in the Developer Console or one generated with your API key through a server SDK.
4. Exchange the Developer JWT for a Vehicle JWT with the Token Exchange API. Request the permissions you need. Idle segments return start and end locations, so include location permission if you want them.
5. Send the Vehicle JWT in the `Authorization` header to the Telemetry API.
6. Query `segments` with `mechanism: idling`. The idling mechanism finds contiguous periods where engine RPM stays in the idle range and requires a DIMO device. The maximum date range is 31 days.
7. Tune detection with `config`. `maxIdleRpm` sets the upper bound for idle RPM (default 1000, min 300, max 3000). `minSegmentDurationSeconds` drops short segments (default 240, min 60, max 3600). `signalCountThreshold` sets how sensitive activity detection is (default 10).
8. Read `duration`, `start`, `end` and `isOngoing` from each segment. If `isOngoing` is true, the segment extends past your query range and `end` is not returned.

## Code

```graphql
query GetIdlingSegments {
  segments(
    tokenId: 117315
    from: "2025-11-01T09:21:19Z"
    to: "2025-11-07T09:21:19Z"
    mechanism: idling
    config: {
      maxIdleRpm: 1000
      minSegmentDurationSeconds: 240
    }
    signalRequests: [
      { name: "speed", agg: MAX }
    ]
    limit: 50
  ) {
    start {
      timestamp
      value { latitude longitude }
    }
    end {
      timestamp
      value { latitude longitude }
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

Send this query to the Telemetry API with the header `{ "Authorization": "<yourVehicleJwt>" }`, replacing `tokenId` with your Corolla's vehicle token ID. The `speed` request adds the maximum speed within each idle segment.

## FAQ

### Which Corolla hardware supports idle detection?
On a Toyota Corolla, both the DIMO LTE R1 (2010 and newer) and the AutoPi (2008 and newer) report idling. The idling mechanism requires a DIMO device.

### Which signal does idle detection depend on?
Idle segments are contiguous periods where engine RPM stays in the idle range. Both the DIMO LTE R1 and the AutoPi report `powertrainCombustionEngineSpeed` for the Corolla.

### How do I change what counts as idle?
Set `maxIdleRpm` in the `config` argument. Windows where the maximum RPM is at or below that value are treated as idle. The default is 1000.

### How do I filter out very short idle periods?
Set `minSegmentDurationSeconds` in `config`. The default is 240 seconds, and the allowed range is 60 to 3600.
