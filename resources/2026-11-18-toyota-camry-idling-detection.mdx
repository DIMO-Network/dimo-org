To detect idling on a Toyota Camry, query the DIMO Telemetry API for segments using the idling detection mechanism. This returns contiguous periods where engine RPM stays in the idle range, and it requires a DIMO device. On a Toyota Camry, both the DIMO LTE R1 and AutoPi report engine RPM and vehicle speed, and DIMO lists idling as an event for each.

DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals. DIMO adds vehicle-state depth on top of GPS tracking; it doesn't replace it.

## Steps

1. Get your `Client ID`, `Redirect URI` and `API Key` from a DIMO Developer License, then get a Developer JWT in the Developer Console or with a server SDK.
2. Have the Camry shared with your app. Vehicle owners consent to and control sharing, so builders get data with clear provenance. Sharing is handled through DIMO Connect.
3. Exchange your Developer JWT for a Vehicle JWT with the Token Exchange API. The Vehicle JWT is scoped to one vehicle and is short-lived. Request the permission that covers non-location data.
4. Send a GraphQL `segments` query to the Telemetry API with `mechanism: idling`, the vehicle's `tokenId`, and a `from` and `to` range of no more than 31 days.
5. Optionally tune detection with `config`. `maxIdleRpm` sets the upper RPM bound for idle (default 1000, min 300, max 3000). `minSegmentDurationSeconds` filters short segments (default 240). `signalCountThreshold` sets how sensitive detection is (default 10).
6. Read `start`, `end`, `duration` and `isOngoing` from each segment. If `isOngoing` is true, the idle period extends past your query range and `end` is not included.

The Camry's vehicle page at /vehicles/toyota/camry lists the signals each connection reports. Idle detection relies on engine RPM (`powertrainCombustionEngineSpeed`), which both the DIMO LTE R1 and AutoPi report on this car. The DIMO LTE R1 also reports ignition status (`isIgnitionOn`).

## Code

This GraphQL query returns idle segments for one vehicle, adding maximum speed per segment as an extra check. Send it to the Telemetry API with your Vehicle JWT in the `Authorization` header. Replace the token ID and dates with your own.

```graphql
query GetIdleSegments {
  segments(
    tokenId: 117315
    from: "2025-11-01T09:21:19Z"
    to: "2025-11-07T09:21:19Z"
    mechanism: idling
    config: { maxIdleRpm: 1000, minSegmentDurationSeconds: 240 }
    signalRequests: [
      { name: "speed", agg: MAX }
    ]
    limit: 50
  ) {
    start {
      timestamp
      value { latitude longitude }
    }
    end {
      timestamp
      value { latitude longitude }
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

## FAQ

### Which Toyota Camry connections support idling detection?
The DIMO LTE R1 and AutoPi both list idling for the Camry, starting with model year 2007 and newer. Both report engine RPM and vehicle speed.

### Do I need hardware to detect idling?
Yes. The idling mechanism requires a DIMO device, so the Camry needs a connected device that reports to DIMO.

### How do I change what counts as idle?
Set `maxIdleRpm` in the `config` argument. Windows where maximum RPM is at or below that value count as idle. The default is 1000.

### How far back can I query?
The `segments` query supports a maximum date range of 31 days. Use `limit` and `after` to page through results, with a default limit of 100 and a maximum of 200.

### How do I get access to the vehicle's data?
The owner must share the vehicle with your app through DIMO Connect. You then exchange your Developer JWT for a Vehicle JWT to query that vehicle.
