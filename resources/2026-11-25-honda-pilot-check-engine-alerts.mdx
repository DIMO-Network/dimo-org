To get check-engine alerts on a Honda Pilot, create a DIMO Vehicle Triggers webhook on the trouble-code count that the DIMO LTE R1 reports. For the Pilot (2009 and newer), the DIMO LTE R1 reports the DTC count and distance with MIL on, and the AutoPi reports only the trouble code list. The two devices list different signals, so there are two separate paths: a webhook alert on a DIMO LTE R1, or polling the code list on an AutoPi. See the [Honda Pilot vehicle page](/vehicles/honda/pilot) for every signal it reports. For any other vehicle, see [how to get check-engine light alerts](/resources/check-engine-light-alerts).

DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals.

## Steps

1. Create a Developer License in the [Developer Console](https://console.dimo.org/sign-in), with its Client ID, Redirect URI and API Key, and get a Developer JWT. Webhooks are tied to the license that creates them.
2. Get the Pilot shared with your app through DIMO Connect. You need a shared vehicle before you can exchange your Developer JWT for a Vehicle JWT.
3. Find out which device the Pilot has. Steps 4 to 6 are for a Pilot with a DIMO LTE R1. Step 7 is for a Pilot with an AutoPi.
4. DIMO LTE R1: call `GET /v1/webhooks/signals` on the Vehicle Triggers API to list the signal names available for webhooks. Confirm that `obdStatusDTCCount` is listed before you build on it.
5. DIMO LTE R1: create a webhook with `service` set to `signals`, `metricName` set to the VSS-prefixed `vss.obdStatusDTCCount`, and the condition `valueNumber > 0`. You can use `vss.obdDistanceWithMIL` instead, which the DIMO LTE R1 also reports on a Pilot. Set `coolDownPeriod` to limit repeat notifications, set `targetURL` to your HTTPS endpoint, and fill in `description`, `status` and `verificationToken`.
6. DIMO LTE R1: subscribe the Pilot to the webhook with `POST /v1/webhooks/:webhookId/subscribe/:tokenDID`, passing the vehicle's DID (for example `did:erc721:137:0xbA5738a18d83D41847dfFbDC6101d37C69c9B0cF:12345`). To cover every vehicle that has shared with your license, use the subscribe-all endpoint instead. The DIMO LTE R1 does not report `obdDTCList` on the Pilot, so the alert tells you a code is active but the codes themselves are not available on this device.
7. AutoPi: it reports `obdDTCList` on the Pilot but no DTC count or distance-with-MIL signal to trigger on, so poll instead. Exchange your Developer JWT for a Vehicle JWT through the Token Exchange API, requesting privilege 1 (all-time, non-location data). Then query `signalsLatest` in the Telemetry API for `obdDTCList` with `value` and `timestamp`, and alert from your own backend when the list changes.

`obdStatusDTCCount` is the number of currently active diagnostic trouble codes. `obdDistanceWithMIL` is the distance travelled with the malfunction indicator lamp (MIL) on, so the two can be used as different alert conditions.

## Code

This cURL request creates the webhook from step 5 for a Pilot with a DIMO LTE R1. Replace `<DEV_JWT>`, the target URL and the verification token with your own values.

```shell
curl -X POST "https://vehicle-triggers-api.dimo.zone/v1/webhooks" \
  -H "Authorization: Bearer <DEV_JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "service": "signals",
    "metricName": "vss.obdStatusDTCCount",
    "condition": "valueNumber > 0",
    "coolDownPeriod": 3600,
    "description": "Fires when a subscribed Honda Pilot reports a DTC count above zero",
    "displayName": "Pilot check-engine alert",
    "targetURL": "https://example.com/webhook-receiver",
    "status": "enabled",
    "verificationToken": "replace-with-your-token"
  }'
```

For a Pilot with an AutoPi, poll the code list from step 7. Use the header `Authorization: Bearer <Vehicle JWT>` and replace `12345` with your vehicle's token ID.

```graphql
query GetTroubleCodes {
  signalsLatest(tokenId: 12345) {
    obdDTCList {
      value
      timestamp
    }
  }
}
```

To start, get a Developer License from the [Developer Console](https://console.dimo.org/sign-in) and follow the [authentication guide](/docs/getting-started/authentication). Webhook endpoints are listed in the [Vehicle Triggers API reference](/docs/api-references/vehicle-triggers-api).

## FAQ

### Which Honda Pilot connection reports the trouble codes themselves?
The AutoPi reports the trouble code list (`obdDTCList`). The DIMO LTE R1 reports a DTC count (`obdStatusDTCCount`) and the distance driven with the check-engine light on.

### Do I need hardware in the Pilot?
Yes. DIMO's data for the Pilot comes from a connected device, either the AutoPi or the DIMO LTE R1. Details are on the [Honda Pilot vehicle page](/vehicles/honda/pilot).

### Can I get the alert without polling?
On a Pilot with a DIMO LTE R1, yes. The Vehicle Triggers API sends a POST to your target URL when the condition is met, so your app doesn't need to poll. On a Pilot with an AutoPi, the AutoPi reports the code list and no other diagnostic signal, so you poll `signalsLatest`.

### Who controls access to the Pilot's data?
Vehicle owners consent to and control sharing, so builders get data with clear provenance. Your app can only subscribe and query vehicles that have been shared with your Developer License.
