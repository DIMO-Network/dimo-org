To track charging sessions on a Tesla Model 3, query the DIMO Telemetry API for recharge segments and request the charge level signal for each one. DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals. On a Tesla Model 3 (2018 and newer), the Tesla OEM cloud connection reports charging status, session energy and charge level, so you can describe each session in detail. The vehicle page is at /vehicles/tesla/model-3.

## Steps

1. Create a developer license and get a Developer JWT in the Developer Console at the [DIMO Developer Console](https://console.dimo.org). You can use the system-generated Developer JWT, or generate one with your API key.
2. Get the Model 3 shared with your app. The owner shares it through DIMO Connect. Vehicle owners consent to and control sharing, so builders get data with clear provenance.
3. Exchange your Developer JWT for a Vehicle JWT by sending a request to the Token Exchange API with the vehicle's token ID and the permissions you need. Charging and battery signals are non-location data, so request the all-time, non-location data permission (privilege 1).
4. Query the `segments` resource of the Telemetry API with `mechanism: recharge`. Pass the vehicle token ID and a time range of at most 31 days. Recharge detection uses charging signals and state of charge. By default it also returns the level signal at the start and end of each segment.
5. Add `signalRequests` to enrich each session. On the Model 3, the Tesla connection reports `powertrainTractionBatteryChargingAddedEnergy` (Session Energy, kWh) and `powertrainTractionBatteryStateOfChargeCurrent` (Current Charge Level, %). Use an aggregation such as `MAX` or `LAST`.
6. Read each segment's `start`, `end`, `duration` and `isOngoing` fields. If `isOngoing` is true, the session extends past your query range and `end` is not returned.
7. For the live state of a session, query `signalsLatest` for `powertrainTractionBatteryChargingIsCharging` and `powertrainTractionBatteryChargingIsChargingCableConnected`.

## Code

This GraphQL query, adapted from the Telemetry API segments documentation, lists recharge sessions with the highest session energy and the last charge level reading. Send it with your Vehicle JWT in the `Authorization` header. Replace the token ID and dates with your own.

```graphql
query GetRechargeSessions {
  segments(
    tokenId: 12345
    from: "2026-11-01T00:00:00Z"
    to: "2026-11-15T00:00:00Z"
    mechanism: recharge
    signalRequests: [
      { name: "powertrainTractionBatteryChargingAddedEnergy", agg: MAX }
      { name: "powertrainTractionBatteryStateOfChargeCurrent", agg: LAST }
    ]
    limit: 50
  ) {
    start {
      timestamp
    }
    end {
      timestamp
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

## FAQ

### Which Tesla Model 3 signals describe a charging session?
The Tesla connection reports Session Energy, Current Charge Level, Charging Status, Charging Cable Connected, Charge Limit, Charging Voltage, AC Current Charge and Battery Power. Their DIMO names are listed on /vehicles/tesla/model-3.

### How do I get the current charging status instead of past sessions?
Use the `signalsLatest` query with the Vehicle JWT and request `powertrainTractionBatteryChargingIsCharging`. Include `value` and optionally `timestamp` in the selection.

### How far back can I query charging sessions?
The `segments` resource accepts a maximum date range of 31 days per query. It returns up to 200 segments per request, and you can page with the `after` argument.

### Do I need the owner's permission?
Yes. You need the vehicle shared with you to fetch a Vehicle JWT, and you request specific permissions in the token exchange.
