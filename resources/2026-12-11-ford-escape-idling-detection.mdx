To detect idling on a Ford Escape, query the DIMO Telemetry API for segments with the idling detection mechanism. It finds contiguous periods where engine RPM stays in the idle range, and it requires a DIMO device. DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals.

On a Ford Escape, idling is supported on both the DIMO LTE R1 (2008 and newer) and the AutoPi (2012 and newer). Both report engine RPM, vehicle speed and engine runtime. Full details are on the vehicle page at [/vehicles/ford/escape](/vehicles/ford/escape).

## Steps

1. Create a Developer License and get a Developer JWT in the Developer Console. You need your Client ID, Redirect URI and API Key. Vehicle owners consent to and control sharing, so builders get data with clear provenance.
2. Get the Ford Escape shared with your app. Use DIMO Connect to request the permissions you need. The vehicle must have a DIMO device connected.
3. Exchange your Developer JWT for a Vehicle JWT for that vehicle by calling the Token Exchange API with the vehicle's token ID and the permissions you need, such as all-time non-location data.
4. Send the Vehicle JWT in the `Authorization` header to the Telemetry API.
5. Query `segments` with `mechanism: idling`, a `from` and `to` range of at most 31 days, and the vehicle token ID.
6. Optionally tune detection with `config`. `maxIdleRpm` sets the upper bound for idle RPM (default 1000, min 300, max 3000). `minSegmentDurationSeconds` filters out short segments (default 240 seconds). `maxGapSeconds` controls when a segment is split (default 300 seconds).
7. Read `start`, `end`, `duration` and `isOngoing` from each segment. If `isOngoing` is true, the segment extends past your query range and `end` is not included.

## Code

This GraphQL query is adapted from the Telemetry API segments documentation. Replace the token ID and time range with your own, and send your Vehicle JWT in the `Authorization` header. It uses `speed`, a signal the Ford Escape reports on both devices. It is not tagged as runnable because it needs a Vehicle JWT for a shared vehicle.

```graphql
query GetIdlingSegments {
  segments(
    tokenId: 117315
    from: "2025-11-01T09:21:19Z"
    to: "2025-11-07T09:21:19Z"
    mechanism: idling
    config: {
      maxIdleRpm: 1000
      minSegmentDurationSeconds: 240
    }
    signalRequests: [
      { name: "speed", agg: MAX }
    ]
    limit: 50
  ) {
    start {
      timestamp
      value { latitude longitude }
    }
    end {
      timestamp
      value { latitude longitude }
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

## FAQ

### Does idling detection on a Ford Escape need hardware?
Yes. The idling mechanism requires a DIMO device. For the Ford Escape, the DIMO LTE R1 and the AutoPi both support idling.

### How does DIMO decide a Ford Escape is idling?
A segment is a contiguous period where engine RPM remains in the idle range. Windows with maximum RPM at or below `maxIdleRpm` count as idle, and the default is 1000.

### How far back can I query?
The maximum date range for a segments query is 31 days. Use `limit` and the `after` cursor to page through results.

### Can I change what counts as idling?
Yes. Set `maxIdleRpm` and `minSegmentDurationSeconds` in the `config` argument, within the documented minimum and maximum values.
