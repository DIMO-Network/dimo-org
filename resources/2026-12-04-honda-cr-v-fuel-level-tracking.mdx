On a Honda CR-V, the DIMO LTE R1 reports fuel as a percentage and as liters, and DIMO can detect refuels from the rise in fuel level. Authenticate with a Developer JWT, exchange it for a Vehicle JWT, then query the Telemetry API for the latest fuel signals and for refuel segments. DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals.

The DIMO LTE R1 is supported on the CR-V from model year 2008 and newer. See the [Honda CR-V vehicle page](/vehicles/honda/cr-v) for the full signal list. The AutoPi connection for this car lists different signals and does not include the fuel signals used here, so the steps below assume a DIMO LTE R1.

## Steps

1. Create a Developer License in the Developer Console and note your Client ID, Redirect URI and API Key.
2. Get the CR-V shared with your app. Vehicle owners consent to and control sharing, so builders get data with clear provenance. Use DIMO Connect to request the share.
3. Get a Developer JWT, either from the Developer Console or with your API key through a server SDK.
4. Send the Developer JWT and the vehicle token ID to the Token Exchange API to get a Vehicle JWT. You need a vehicle shared with you first. Request the permissions your app needs when you exchange.
5. For the current fuel state, call `signalsLatest` in the Telemetry API with the Vehicle JWT in the `Authorization` header. Ask for `powertrainFuelSystemRelativeLevel` (Fuel Percentage, %) and `powertrainFuelSystemAbsoluteLevel` (Fuel Level, liters), each with `value` and `timestamp`.
6. For refuels, call the `segments` query with `mechanism: refuel`. This detects where fuel level rises significantly. Keep the date range to 31 days or less.
7. Read each segment's `start`, `end` and `duration`. Refuel segments also include the level signal at the start and end by default. You can add `powertrainFuelSystemRelativeLevel` with `FIRST` and `LAST` aggregations to request them explicitly.
8. To adjust sensitivity, set `minIncreasePercent` in `config`. It is the minimum percent increase within a window to count as a level increase, and the default is 15.

## Code

```graphql
# Header: { "Authorization": "<yourVehicleJwt>" }

query GetRefuels {
  segments(
    tokenId: 12345
    from: "2025-11-01T09:21:19Z"
    to: "2025-11-07T09:21:19Z"
    mechanism: refuel
    config: { minIncreasePercent: 15 }
    signalRequests: [
      { name: "powertrainFuelSystemRelativeLevel", agg: FIRST }
      { name: "powertrainFuelSystemRelativeLevel", agg: LAST }
    ]
    limit: 50
  ) {
    start {
      timestamp
      value { latitude longitude }
    }
    end {
      timestamp
      value { latitude longitude }
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

## FAQ

### How do I read the current fuel level on a Honda CR-V?
Query `signalsLatest` with the vehicle token ID and request `powertrainFuelSystemRelativeLevel` for percent or `powertrainFuelSystemAbsoluteLevel` for liters. Both are reported by the DIMO LTE R1 on this car.

### Does the AutoPi connection report fuel level or refuels on the CR-V?
No. For the CR-V, the AutoPi connection lists speed, engine RPM, engine load, low voltage battery, throttle position, altitude, coordinates and idling events. Fuel level and refuel detection come from the DIMO LTE R1.

### How far back can I query refuel segments?
The `segments` query has a maximum date range of 31 days. For longer periods, run several queries and use the `after` cursor to page through results.

### Why was a small top-up not detected as a refuel?
Refuel detection looks for a significant rise in fuel level, and `minIncreasePercent` defaults to 15. Lower that value in `config` to make detection more sensitive.
