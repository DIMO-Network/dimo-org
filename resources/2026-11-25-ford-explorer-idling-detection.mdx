To detect idling on a Ford Explorer, query the DIMO Telemetry API for trip segments using the idling detection mechanism. On a Ford Explorer, the DIMO LTE R1 (2013 and newer) and AutoPi (2008 and newer) both report engine RPM (`powertrainCombustionEngineSpeed`) and support idling events. Idling segments are contiguous periods where engine RPM stays in the idle range, and this mechanism requires a DIMO device. See the [Ford Explorer vehicle page](/vehicles/ford/explorer) for the full signal list. For any other vehicle, see [how to detect vehicle idling](/resources/detect-vehicle-idling).

## Steps

1. Create a Developer License in the [Developer Console](https://console.dimo.org/sign-in) and note its Client ID, Redirect URI and API Key.
2. Get a Developer JWT, either the system-generated one in the console or one generated with your API key through a server SDK.
3. Have the Explorer's owner share the vehicle with your app through DIMO Connect. You need a vehicle shared with you before you can fetch a Vehicle JWT.
4. Exchange your Developer JWT for a Vehicle JWT by sending a request to the Token Exchange API with the vehicle's token ID. Ask for privilege 1 (all-time, non-location data) and privilege 4 (all-time location); the `segments` query requires both.
5. Send the Vehicle JWT in the `Authorization` header of a Telemetry API request. Call the `segments` query with `mechanism: idling`, a `from` and `to` range of at most 31 days, and the vehicle token ID.
6. Tune detection with `config`. `maxIdleRpm` sets the upper bound for idle RPM (default 1000, minimum 300, maximum 3000). `minSegmentDurationSeconds` drops short segments (default 240). `signalCountThreshold` sets how sensitive activity detection is (default 10).
7. Read each returned segment's `start`, `end`, `duration` and `isOngoing`. If `isOngoing` is true, the idle period extends past your query range and `end` is not included.

## Code

```graphql
# Header: { "Authorization": "Bearer <yourVehicleJwt>" }
query GetIdlingSegments {
  segments(
    tokenId: 12345
    from: "2026-11-01T00:00:00Z"
    to: "2026-11-07T00:00:00Z"
    mechanism: idling
    config: { maxIdleRpm: 1000, minSegmentDurationSeconds: 240 }
    signalRequests: [
      { name: "powertrainCombustionEngineSpeed", agg: AVG }
    ]
    limit: 50
  ) {
    start {
      timestamp
      value { latitude longitude }
    }
    end {
      timestamp
      value { latitude longitude }
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

Replace `12345` with your Explorer's token ID before you run it. From here, get a Developer License in the [Developer Console](https://console.dimo.org/sign-in) and follow the [authentication guide](/docs/getting-started/authentication) to make the request.

## FAQ

### Do I need hardware to detect idling on an Explorer?
Yes. The idling mechanism requires a DIMO device. For the Explorer, the DIMO LTE R1 and AutoPi both report idling events.

### Which model years does this cover?
The DIMO LTE R1 is listed for 2013 and newer Explorers. The AutoPi is listed for 2008 and newer.

### How do I change what counts as idle?
Set `maxIdleRpm` in `config`. Windows where the maximum RPM is at or below that value are treated as idle.

### How many segments can one request return?
The default `limit` is 100 and the maximum is 200. Use the `after` argument with the start timestamp of the last segment to page through results.
