To track charging sessions on a Tesla Model S, query the DIMO Telemetry API for recharge segments and request the charging signals you want for each one. DIMO gives developers API access to vehicle-state data: diagnostics, fault codes, battery and fuel health, odometer, and maintenance signals. On a Tesla Model S (2013 and newer), the Tesla OEM cloud connection reports charging status, session energy and charge level, and DIMO supports recharge events for it. See the [Tesla Model S vehicle page](/vehicles/tesla/model-s).

## Steps

1. Create a Developer License and get your `Client ID` and `API Key` from the [Developer Console](https://console.dimo.org).
2. Get the Model S shared with your app through DIMO Connect. Vehicle owners consent to and control sharing, so builders get data with clear provenance. You need a vehicle shared with you to fetch a Vehicle JWT.
3. Get a Developer JWT, then exchange it for a Vehicle JWT for that vehicle through the Token Exchange API. Request the permission for all-time, non-location data.
4. Query the `segments` resource of the Telemetry API with `mechanism: recharge`. This detection mechanism uses charging signals and state of charge to find each session. The query range can be at most 31 days.
5. In `signalRequests`, ask for the Model S signals you need per session. Two that suit this job are `powertrainTractionBatteryChargingAddedEnergy` (Session Energy, in kWh) and `powertrainTractionBatteryStateOfChargeCurrent` (Current Charge Level, in %). Other Model S signals, such as `powertrainTractionBatteryChargingIsCharging` (Charging Status) and `powertrainTractionBatteryChargingChargeLimit` (Charge Limit), can be read with `signalsLatest`.
6. Read each segment's `start` and `end` timestamps and `duration`, plus its `signals`. If `isOngoing` is true, the session extends past your query range and `end` is not included.
7. To tune detection, pass a `config` with `minIncreasePercent`, which sets the minimum percent increase within a window that counts as a level increase for recharge detection. The default is 15.

## Code

This is a GraphQL query adapted from the Telemetry API segments example. Send it with your Vehicle JWT in the `Authorization` header. Replace the token ID and dates with your own.

```graphql
query GetChargingSessions {
  segments(
    tokenId: 12345
    from: "2026-11-01T00:00:00Z"
    to: "2026-11-15T00:00:00Z"
    mechanism: recharge
    signalRequests: [
      { name: "powertrainTractionBatteryChargingAddedEnergy", agg: MAX }
      { name: "powertrainTractionBatteryStateOfChargeCurrent", agg: LAST }
    ]
    limit: 50
  ) {
    start {
      timestamp
    }
    end {
      timestamp
    }
    duration
    isOngoing
    startedBeforeRange
    signals { name agg value }
  }
}
```

## FAQ

### Which Model S connection reports charging data?
The Tesla OEM cloud connection, for 2013 and newer model years, reports the charging signals used here, including session energy, charging status, charge limit and cable connected. It also supports recharge events.

### How does DIMO detect a charging session?
The `recharge` detection mechanism is a hybrid method. It uses charging signals and state of charge to find where the charge level rises.

### How far back can I query?
The `segments` query has a maximum date range of 31 days. It returns 100 segments by default, up to a maximum of 200 per request, and you can paginate with the `after` argument.

### Does this replace GPS tracking?
No. DIMO adds vehicle-state depth on top of GPS tracking; it doesn't replace it.
